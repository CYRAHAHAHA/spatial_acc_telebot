## Project Overview

This repository integrates Autodesk Construction Cloud (ACC) with Telegram for real-time construction site updates. It consists of three main components:

1. **Flask Web App** (`root/`) - Web interface and API for ACC integration
2. **Telegram Bot** (`telebot/`) - Parses site updates from Telegram and syncs to ACC
3. **Auth utilities** (`auth/`) - Standalone authentication scripts

The core workflow: Telegram messages with `[UPDATE]` format → Bot parses and logs → Flask API receives update → ACC Assets API updates status using GUID (IFC Global ID).

## Running the Application

### Flask Web App (Port 8080)
```bash
# Navigate to root directory
cd root
python main.py
```
The app runs on `http://localhost:8080` and serves a SPA at `/`.

### Telegram Bot
```bash
# Navigate to telebot directory
cd telebot
export TELEGRAM_TOKEN="your-bot-token"
export FLASK_BASE="http://localhost:8080"  # optional, defaults to this
export SITE_UPDATES_TOKEN="super-secret-token"  # must match flask_api.py
python bot_logger.py
```

### Flask API Server (for Telegram integration)
```bash
# Navigate to telebot directory
cd telebot
python flask_api.py
```
This runs on `http://0.0.0.0:8080` and receives POST requests from `bot_logger.py`.

## Environment Configuration

Create a `.env` file in `root/` with the following structure:
```
YR_CLIENT_ID=your_autodesk_client_id
YR_CLIENT_SECRET=your_autodesk_client_secret
YR_REDIRECT_URI=http://localhost:8080/callback
YR_SCOPES=data:read data:write data:create
YR_PROJECT_ID=your_acc_project_id
```

The config system (root/app/config.py) supports multiple users by prefixing env vars (e.g., `YR_`, `ANOTHER_USER_`). Switch users via `GET /switch_user/<user>`.

## Architecture

### Flask App Structure (`root/app/`)

- **`__init__.py`**: Initializes Flask app, CORS, AutodeskAuth token manager. Serves SPA from `app/src/`.
- **`routes.py`**: HTTP endpoints for OAuth flow, creation, updates, fetches, and API routes for the SPA.
- **`authentication.py`**: `AutodeskAuth` class managing OAuth tokens with auto-refresh. Persists tokens to `autodesk_tokens.json`.
- **`config.py`**: Loads env vars with user prefixes (e.g., `YR_CLIENT_ID`). Singleton `config` instance.
- **`utils.py`**: Contains `@require_access_token` decorator to guard protected endpoints.

### Key Functions (`root/app/functions/`)

- **`fetch_assets_config.py`**: Fetches project config from ACC, writes `status_sets.csv`, `custom_fields.csv`, `categories.csv` to `data/`.
- **`fetch_all_assets_info.py`**: Fetches all assets (paginated), writes `assets_total.csv` with columns including `ifc_global_id` and `B3F_id`.
- **`create_status_sets.py`**: POSTs status sets to ACC from JSON array.
- **`create_custom_fields.py`**: POSTs custom fields to ACC from JSON array.
- **`update_status.py`**:
  - Looks up `status_id` from `data/status_sets.csv` by `status_label`.
  - Resolves `B3F_id` from `ifc_global_id` in `data/assets_total.csv`.
  - PATCHes ACC Assets Batch v2 API: `PATCH /construction/assets/v2/projects/{projectId}/assets:batch-patch` with body `{"<B3F_id>": {"statusId": "<statusId>"}}`.

### Telegram Bot (`telebot/bot_logger.py`)

- Listens for Telegram group messages starting with `[UPDATE]`.
- Parses structured fields: Location, Zone/Grid/Area, Task, Status, Date, Remarks, GUID.
- Canonicalizes values using fuzzy matching (e.g., "complted" → "Completed").
- Enforces required fields and validates against canonical lists (`TASKS_CANON`, `STATUSES_CANON`).
- Logs valid updates to `logs/log_message.jsonl`.
- If GUID is present, sends parsed data to Flask API (`POST /site-updates/{guid}`).
- Use `/template` command in Telegram to get update format template.

### Flask API (`telebot/flask_api.py`)

- Receives `POST /site-updates/{guid}` from bot with bearer token auth.
- Validates GUID format (UUID).
- Appends entry to `site_updates.json` (JSON array, pretty-printed).
- If status is provided:
  - Gets Autodesk access token via `AutodeskAuth`.
  - Calls `update_assets()` from `root/app/functions/update_status.py`.
  - Returns combined response (local log + ACC update result).

## Important Data Flow

1. **Preview vs Creation**:
   - Preview endpoints (`/api/preview/*`) read from CSV files generated by fetch functions.
   - Creation endpoints (`/create_*_from_json`) accept JSON payloads from `/api/payload/*` routes which serve hardcoded JSON files in `data/`.

2. **Status Update Flow**:
   - Telegram: `[UPDATE]` with GUID → bot parses → `POST /site-updates/{guid}` with status
   - Flask API: status label → lookup `status_id` in CSV → GUID → lookup `B3F_id` in CSV
   - ACC: `PATCH assets:batch-patch` with `{"B3F_id": {"statusId": "status_id"}}`

3. **CSV Generation**:
   - `GET /fetch_assets_config` writes status_sets.csv, custom_fields.csv, categories.csv
   - `GET /fetch_all_assets_info` writes assets_total.csv with IFC GUID mappings
   - CSVs include `sep=,` header for Excel compatibility

## Key API Endpoints

### OAuth & User Management
- `GET /authorize` - Start Autodesk OAuth flow
- `GET /callback` - OAuth callback handler
- `GET /switch_user/<user>` - Switch to different user credentials

### Asset Operations
- `POST /update_status` - Update asset status via GUID (body: `{asset_guid, status_value}`)
- `GET /fetch_assets_config` - Fetch and cache ACC config to CSVs
- `GET /fetch_all_assets_info` - Fetch all assets to CSV

### Creation (Protected)
- `POST /create_status_sets_from_json` - Create status sets from JSON
- `POST /create_custom_fields_from_json` - Create custom fields from JSON

### SPA API Routes
- `GET /api/status` - Token validity and environment info
- `GET /api/categories` - Categories with hierarchy
- `GET /api/preview/status_sets` - Status sets from CSV (grouped)
- `GET /api/preview/custom_fields` - Custom fields from CSV
- `GET /api/payload/status_sets` - Hardcoded JSON payload (`data/new_status_sets.json`)
- `GET /api/payload/custom_fields` - Hardcoded JSON payload (`data/new_custom_fields.json`)

### Telegram Integration
- `POST /site-updates/{guid}` - Receives parsed updates from bot (requires bearer token)

## Working with CSVs

CSVs are stored in `root/data/` and include:
- **status_sets.csv**: status_set_id, status_set_name, status_id, status_label
- **custom_fields.csv**: field definitions with enum values
- **categories.csv**: category hierarchy
- **assets_total.csv**: All assets with `ifc_global_id` (GUID) and `B3F_id` (ACC internal ID)

When reading CSVs, use `encoding="utf-8-sig"` to handle BOM and `sep=","` to respect Excel hint.

## Authentication Flow

1. User visits `/authorize` → redirects to Autodesk OAuth
2. User grants permissions → Autodesk redirects to `/callback?code=...`
3. App exchanges code for tokens via `AutodeskAuth.exchange_code_for_tokens()`
4. Tokens saved to `autodesk_tokens.json` (access token, refresh token, expiry)
5. `AutodeskAuth.get_access_token()` auto-refreshes expired tokens
6. Protected routes use `@require_access_token` decorator

## Telegram Update Format

```
[UPDATE]
Location: Building A, Level 3
Zone / Grid / Area: Grid 5-7, East Wing
Task: Internal Partition Walls
Status: Completed
Date: 17 Oct 2025
Remarks: Ready for inspection
GUID: 12345678-1234-1234-1234-123456789012
```

**Required fields**: Location, Zone/Grid/Area, Task, Status
**Optional**: Date (uses message date if omitted), Remarks, GUID
**GUID format**: Standard UUID (used as IFC Global ID to identify assets in ACC)

## Canonical Value Lists

Defined in `telebot/bot_logger.py`:
- **Buildings**: Building A, Building B, Building C, Block A, Block B
- **Levels**: B3, B2, B1, 1-7
- **Tasks**: Internal Partition Walls, Masonry Walls, Drywall, Slab, MEP Rough-in, Painting
- **Statuses**: Completed, In Progress, Delayed, Issue

Bot uses fuzzy matching (difflib) with 60% cutoff to correct typos.

## IFC Files

`model_files/` contains IFC (Industry Foundation Classes) files used for BIM model imports. These are large binary files (10-30MB each) containing building geometry and metadata.

## Testing the Integration

1. Start Flask web app: `cd root && python main.py`
2. Authenticate: Visit `http://localhost:8080/authorize`
3. Fetch config: `GET /fetch_assets_config` (populates CSVs)
4. Fetch assets: `GET /fetch_all_assets_info` (populates assets_total.csv with GUIDs)
5. Start Flask API: `cd telebot && python flask_api.py`
6. Start Telegram bot: `cd telebot && python bot_logger.py`
7. Send `[UPDATE]` message in Telegram group with valid GUID
8. Verify: Check `telebot/site_updates.json` and ACC Assets for status update
